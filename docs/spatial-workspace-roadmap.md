# 空间工作区路线图（探索分支）

> 分支：`feat/ai-spatial-workspace`
> 当前状态：P0 骨架 + 无边界视觉已完成，六种形态可切换，默认关闭。
> 本文回答两个问题：接下来做什么、每阶段怎么算通过。

---

## 已完成的 P0

- SceneSpec 协议 + 不可信输入规范化
- 确定性布局引擎（离散区域、球体让位切分、折叠 chip）
- `<ai-spatial-stage>`：渲染器/来源双注册表、FLIP、入场/退场
- orb 接受外部布局计划（让位、缩小、停靠左下）
- 对话层支持任意矩形与底部字幕
- 六种空间形态：companion / split-left / split-right / stage / immersive / focus
- 无边界漂浮视觉：无卡片底、mask 羽化、单峰值强调、等距 3D 占位
- 运行时开关，关闭即回退原两态布局

## P1 —— 内容能力（分支内，预计 1–2 天）

目标：让「展示源可扩展」从口号变成可验证的能力。

| 事项 | 说明 |
|---|---|
| 补齐渲染器 | `timeline`、`image`、`media`（视频/音频）、`diff`（代码差异） |
| 来源适配器 | `relay-tool`（复用现有 function call 结果）、`mcp-chart`、`flint`、`html`（默认关闭） |
| 能力自省 | 暴露 `listRenderers()` 的能力清单，供提示词与布局共同使用 |
| 长内容 | 表格/卡片虚拟化阈值；超过 200 行降级为分页或摘要 |
| 空/错/慢 | 每个渲染器统一 loading / empty / error 三态 |

**通过标准**

- 新增一种 kind 只需一个文件 + 一次 `registerRenderer`，不改协议与布局；
- 未知 kind 走兜底视图，不抛异常、不影响语音；
- 1280×720 下六种模式稳定 60fps（不含 3D 全屏）；
- 12 种典型内容（长表格、双系列折线、单指标、结论、3D、HTML）都能落在合理槽位。

## 现实选择：Markdown 捕获（已完成，替代 P2 的第一步）

原计划是用独立视觉路由模型产出 SceneSpec。实际先落了一个更轻的方案：

- 检索智能体在正文后追加 ```chart 块（md 表格或 JSON）；
- 中继在回灌语音模型前剥离该块 → **数据不会被念出来**；
- 前端解析并渲染：1 块 → 右分栏；2 块以上 → 全局。

好处：零额外模型调用、零 schema、提示词即可控。
代价：只有检索工具会出图；知识库多生成一段表格，处在语音等待路径上。

**旁路补齐已完成**（2026-10-19）：

- `/kb` 正文请求不再携带任何图表参数，与主线一致；
- 新增 `/kb/chart` 只产出图表块，与正文**同时**发出；
- 新轮次 abort 旧请求、晚到结果按 epoch 丢弃、挂断即取消；
- `shouldRequestChart()` 做成本门控，普通制度问答不触发；
- 前端有 `chart_request / chart_ready / chart_skip` 埋点，中继有 `kb_chart`。

待办：知识库恢复后用 10 个真实问题核对
①`has_chart` 命中率 ②`ms` 分布 ③首声延迟相对主线的增量。

## P2 —— 语义路由与场景契约（3–4 天，在捕获方案稳定后）

目标：从「检索工具出图」扩展到「任何回答都能按内容生成场景」，且不牺牲第一声延迟。

### 中继接口

新增一条与语音并行的视觉通道，不阻塞音频：

```
用户说完
  → 语音回答立即开始（首包目标不变）
  → 同时后台视觉路由（不阻塞）
  → 回答进行到 50% 时场景 spec 就绪
  → 回答结束前 300–800ms 预挂载
  → 结束或指代句处入场
```

- 新增 `/view` 或 WS `scene` 消息，载荷为 SceneSpec；
- 校验失败回灌 `VALIDATION_FAILED`，模型重试一次，仍失败则纯文本；
- 置信度 < 0.6 不出图；
- 路由分类先收敛到 7 类：`text / table / chart / flow / map / compare / calculator`。

### 通过标准

- 10 句脚本化问题 → 稳定得到预期模式（人工验收）；
- 首包音频延迟相对主线 **不增加**（±50ms 内）；
- 非法 spec 100% 回退文本，不出现空白舞台；
- 每条场景带 `turnId / route / confidence / layoutRev / reason` 日志，可回放。

### 风险

- 视觉任务与语音共用 GPU/主线程时可能互相抢；需要给 3D 设帧率与 DPR 上限；
- 路由提示词要防止「为了展示而展示」，纯文本必须是一等输出。

## P3 —— 空间智能（3–5 天）

目标：让空间有记忆、可干预、有因果。

| 事项 | 说明 |
|---|---|
| 空间记忆 | 按会话持久化场景与用户覆盖；刷新/重进恢复上次布局 |
| 用户干预 | pin、拖拽、折叠、撤销；用户动过的面板不再自动重排 |
| 焦点跟随 | 语音提到某块内容时，该面板获得焦点态（不改变位置） |
| 过渡因果 | 大内容入场：球先让位 → 内容再入场；退场反过来 |
| 多标签 | 只同步 SceneSpec 与焦点，几何各端本地计算 |
| 布局回放 | 由日志重放任意一轮布局，便于定位抖动 |

**通过标准**

- 同一会话内 slot retention > 90%（面板不无故换边）；
- 每轮最多一次大重排，5 秒内最多两次；
- 切换模式 time-to-stable < 350ms；
- 用户 pin 过的面板在任何自动重排中位置不变。

---

## P4 —— 生态与生产化（按需）

- **three.js 场景适配器**：替换 `scene3d` 占位实现，模型只传场景描述（相机、图层、数据、样式），不传代码；
- **Flint / MCP 图表**：作为 SourceAdapter 接入，不写进核心协议；
- **visualise 沙箱 HTML**：保持 opt-in，双层 iframe，无同源存储、无任意网络；
- **性能分级**：低端设备关闭 `backdrop-filter`、降低粒子与 3D DPR、字幕降为纯文字；
- **无障碍**：面板键盘可达、`prefers-reduced-motion` 全链路、读屏播报场景变化；
- **安全**：CSP、沙箱审计、展示内容中的文字不得触发高权限动作（只能走受校验 action）。

## 指标（从 P2 起持续记录）

| 指标 | 目标 |
|---|---|
| 首包音频延迟增量 | ≤ +50ms |
| 视觉就绪时间 | ≤ 回答结束 + 800ms |
| 非法场景回退率 | 100% 回退成功 |
| 每轮大重排次数 | ≤ 1 |
| slot retention | > 90% |
| 布局确定性 | 同输入同输出（已有自动化校验） |
| 低端机帧率 | ≥ 45fps（关闭模糊后） |

---

## 明确不做（现阶段）

- 不让模型输出像素坐标或任意 CSS；
- 不引入全局 Cassowary 求解（离散区域已足够，且更可复现）；
- 不做「每次对话重新生成整个界面」——空间记忆优先；
- 不在核心协议里绑定任何一家图表服务。
